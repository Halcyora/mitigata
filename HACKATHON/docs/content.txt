It’s too strict for practical use if the goal is to catch most real correlations. It favors precision, but risks false negatives when scanners classify the same issue with different CWE IDs or when ZAP omits request-parameter details. Your Flask reports already show disjoint CWE sets, so relaxing the parameter check alone still wouldn’t create a match.

CWE equivalences should be added only when validated; matching on route and a loosely related CWE alone could create false positives.
